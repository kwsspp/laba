## Этап 3. Ветвление (Branching) и параллельная разработка

14. **Создание и переключение на новую ветку.** Командой `git branch mybranch` создана новая ветка, выполнен просмотр списка веток (`git branch`) и переход в нее с помощью `git switch mybranch`.
    ![Создание и переключение на ветку mybranch](14.jpg)

15. **Создание файла в ветке `mybranch`.** Создан файл `file1.txt` с текстом `"Никита"`, выполнен его коммит (`5ac8a0f` — `Add file1.txt`). Граф истории (`git log --oneline --graph`) показывает, что `mybranch` ушла вперед от `main` на один коммит.
    ![Коммит file1.txt в ветке mybranch](15.jpg)

16. **Параллельное изменение в ветке `main`.** После возврата в `main` создан файл `file2.txt` с текстом `"File in main"` и зафиксирован коммитом `6e4442d` (`Add file2.txt`). Команда `git log --oneline --graph --all` наглядно отображает расхождение веток `main` и `mybranch` от общего родителя `5896a01`.
    ![Расхождение веток main и mybranch на графе коммитов](16.jpg)

17. **Сравнение веток через `git diff` и обновление документации.** В ветке `mybranch` выполнена команда `git diff mybranch main`, показавшая разницу между ветками (удаление `file1.txt` и добавление `file2.txt` при переходе к `main`). Затем обновлен `README.md` и сделан коммит `6289ff4` (`Update README in mybranch`).
    ![Сравнение веток через git diff и коммит в README.md](17.jpg)

18. **Публикация ветки `mybranch` и синхронизация `main`.** Новая ветка впервые отправлена на GitHub (`git push -u origin mybranch`), после чего выполнен переход в `main` и отправка коммита `6e4442d` на сервер (`git push`).
    ![Пуш ветки mybranch и обновление main на GitHub](18.jpg)

## Этап 4. Сравнение изменений (`git diff`) и управление откатами (`git restore`)

19. **Расширение кода в `sort.c`.** В ветке `mybranch` в файл `sort.c` добавлены заголовочный файл `#include <stdio.h>` и функция `main()` с тестовым массивом `{4, 2, 0}`.
    ![Обновление файла sort.c с добавлением функции main](19.jpg)

20. **Просмотр неиндексированных изменений (`git diff`).** Команда `git diff` показала построчную разницу между рабочим каталогом и индексом: добавление `#include <stdio.h>`, удаление старых комментариев и появление функции `main()`.
    ![Вывод git diff для неиндексированных изменений](20.jpg)

21. **Просмотр индексированных изменений (`git diff --staged`).** После выполнения `git add sort.c` команда `git diff` вывела пустой результат (все правки в индексе), а `git diff --staged` отобразила изменения, подготовленные к коммиту.
    ![Сравнение работы git diff и git diff --staged](21.jpg)

22. **Комбинирование изменений в индексе и рабочем каталоге.** Утилитой `sed` массив в `sort.c` изменен с `{4, 2, 0}` на `{4, 2}`. Команда `git diff` зафиксировала именно это локальное изменение поверх уже проиндексированной версии файла.
    ![Локальная правка файла поверх проиндексированной версии](22.jpg)

23. **Проверка содержимого индекса.** Повторный вызов `git diff --staged` подтвердил, что в индексе по-прежнему хранится версия с массивом `{4, 2, 0}`.
    ![Проверка состояния индекса через git diff --staged](23.jpg)

24. **Анализ двойного состояния файла в `git status`.** Команда `git status` показала `sort.c` одновременно в двух разделах: зеленым в разделе *«Изменения, которые будут включены в коммит»* и красным в разделе *«Изменения, которые не в индексе для коммита»*.
    ![Отображение файла в индексе и рабочем каталоге одновременно](24.jpg)

25. **Снятие файла с индексации (`git restore --staged`).** Командой `git restore --staged sort.c` файл убран из области подготовленных файлов, при этом все внесенные изменения сохранились в рабочем каталоге.
    ![Убираем файл из индекса командой git restore --staged](25.jpg)

26. **Фиксация изменений и просмотр сокращенного лога.** Изменения в `sort.c` заново проиндексированы и зафиксированы коммитом `f03e342` (`Add main function to sort.c`). Вывод `git log --oneline` показал обновленную историю ветки `mybranch`.
    ![Коммит функции main в sort.c и проверка git log --oneline](26.jpg)

27. **Модификация `sort.c` перед проверкой отката.** С помощью `sed` перед `return 0;` добавлен вызов `printf("hello git\n");`, а вывод `cat sort.c` подтвердил изменение содержимого файла.
    ![Добавление вывода hello git в функцию main](27.jpg)

28. **Фиксация неиндексированной правки в статусе.** Вызов `git status` подтвердил наличие неиндексированных изменений в `sort.c` и подсказку по использованию `git restore`.
    ![Проверка статуса перед откатом изменений](28.jpg)

29. **Откат изменений в рабочем каталоге (`git restore`).** Командой `git restore sort.c` последние локальные правки отменены: вывод `cat sort.c` подтвердил, что строка `printf("hello git\n");` удалена и файл вернулся к состоянию последнего коммита.
    ![Откат локальных изменений командой git restore](29.jpg)

30. **Проверка чистоты рабочего каталога после отката.** Повторный вызов `git status` показал, что несохраненных изменений в рабочем каталоге больше нет, а ветка `mybranch` опережает `origin/mybranch` на 1 коммит.
    ![Проверка статуса репозитория после выполнения git restore](30.jpg)

31. **Отправка обновлений ветки `mybranch` на GitHub.** Коммит `f03e342` успешно отправлен в удаленный репозиторий командой `git push`.
    ![Отправка коммита f03e342 в ветку origin/mybranch](31.jpg)

## Этап 5. Работа с веткой `feature/uppercase`, слияние и разрешение проблем

33. **Создание ветки `feature/uppercase`.** От актуального состояния `main` создана и активирована новая ветка `feature/uppercase` (`git branch` + `git switch`), а команда `git status` подтвердила переход.
    ![Создание и переключение на ветку feature/uppercase](33.jpg)

34. **Изменение файла в новой ветке и обработка опечатки.** В файл `greeting.txt` записано `"HELLO"` в верхнем регистре и выполнена индексация (`git add greeting.txt`). При попытке сделать коммит допущена опечатка в команде (`git comit`), о чем Git корректно предупредил и подсказал правильное написание (`commit`).
    ![Изменение greeting.txt и обработка опечатки в команде git](34.jpg)

35. **Переключение веток с несохраненными изменениями и проверка `merge`.** При переключении обратно на `main` (`git switch main`) не зафиксированное изменение в `greeting.txt` (помеченное флагом `M`) перенеслось в рабочий каталог `main`. После исправления опечатки в имени ветки (`feature/uppercae` -> `feature/uppercase`) команды `git diff` и `git merge` показали, что ветки находятся на одном коммите (*«Уже актуально»*).
    ![Переключение на main и проверка слияния с feature/uppercase](35.jpg)

36. **Удаление ветки и демонстрация конфликта перезаписи при `merge`.** Ветка `feature/uppercase` удалена (`git branch -d feature/uppercase`). Попытка влить `mybranch` в `main` (`git merge mybranch --no-edit`) завершилась сбоем, так как в рабочем каталоге оставались несохраненные локальные изменения в `lab9_git/greeting.txt`, которые могли быть перезаписаны. Просмотр `git log --oneline --graph --all` отразил полную структуру веток.
    ![Удаление ветки и ошибка слияния из-за локальных изменений](36.jpg)

37. **Финальная синхронизация с удаленным репозиторием.** Локальные коммиты ветки `main` (`d4e7cd5` и `8216f04`) успешно отправлены на GitHub с помощью команды `git push`.
    ![Финальный git push ветки main на GitHub](37.jpg)
